## E-10.2 Reglas obligatorias de privacidad y RBAC

1. **No agregar actor–operación al manifiesto:** UC-14 continúa exclusiva de VENDEDOR. ADMIN puede ver datos necesarios **en su subflujo UC-29**, pero no obtiene permiso de consulta financiera universal ni API reutilizable UC-14 por inferencia. REPARTIDOR no ejecuta UC-29; VENDEDOR no ejecuta rendición.
2. **Menor privilegio por objeto y campo:** filtrar por Pedido/recorrido/Cliente específico, y aplicar revalidación en servicio y en controlador. Una ruta de búsqueda contextual UC-34/33 no convierte al actor en lector de toda información financiera del Cliente. No exponer \`IMP-B\` bruto, claves/token, datos bancarios o credenciales fuera de proyección autorizada.
3. **Diferencias y custodia:** un ADMIN ve evidencia y clasificación necesarias para rendir, no todas las transacciones del cliente. Una diferencia de caja no debe presentarse como dinero pagado; el recibo distingue «declarado», «recibido», «atribuido», «provisional» y «confirmado».
4. **Evidencias de separación:** uso de foto, firma y archivos P2b de UC-07 **no** es obligatorio en la rendición de UC-29 de este primer corte; la evidencia mínima estructurada RD-F04-002 sí lo es. No copiar acceso a documentos confidenciales de ofertas/reembolsos.
5. **Permisos de reserva y anulación:** VENDEDOR y ADMIN pueden registrar reserva en Cobro manual cuando existe operación autorizada; ADMIN exclusivamente corrige/libera excepcionalmente reserva, anula Cobro general y recibe rendición. Un cambio de firma/endpoint requerirá adenda propia y test de autorización.

## E-10.3 Matriz mínima de pruebas negativas **a ejecutar posteriormente**

| Escenario | Resultado |
|---|---|
| ADMIN intenta invocar UC-14 como lectura general | Rechazado, aunque tenga acceso a datos limitados en contexto UC-29 |
| VENDEDOR intenta recibir/cerrar rendición | Rechazado; su Cobro manual general sigue permitido |
| REPARTIDOR intenta ejecutar UC-29 o consultar deuda global Cliente | Rechazado; solo UC-05 y acuse de sus propias Entregas |
| REPARTIDOR consulta Pedido de otro reparto/no asignado | Rechazado, sin exposición de importes |
| ADMIN consulta rendición de otro contexto no autorizado | Rechazado; proyección solo del recorrido permitido |
| VENDEDOR intenta anular Cobro manual o liberar reserva excepcionalmente | Rechazado; ADMIN exclusivamente |
| ADMIN registra rendición con diferencia sin observación/motivo requerido | No se confirma cierre/conciliación |
| Dos Clientes comparten recorrido y falta dinero sin atribución | No crear Cobro de Cliente incorrecto; no prorratear sin evidencia |
| Efectivo de custodia sin Cobro confirmado | No mostrar como Pago ni Caja de ventas; sí aparece en control físico administrativo |
| Saldo confirmado y provisional diferentes | Mostrar magnitudes distintas a VENDEDOR; no usar \`D_e\` íntegro como \`V_e\` |
